# 2026-09-11

## 新增：网络路由开关工具（WiFi 走内网 / USB 走外网）

用户需求：写一个可开关的路由脚本，当前用 WiFi 访问内网、USB(手机共享/NDIS) 访问外网。

交付物（本仓库新增 `tools/` 目录）：
- `tools/net-route-switch.ps1` — 主脚本，`-Action on|off|status`，无参数进交互菜单
- `tools/net-route-switch.bat` — 双击启动器（纯 ASCII，`cd /d %~dp0` + 相对路径调用，规避 cmd 中文路径编码问题）

逻辑：
- on：USB 网卡接口度量设 10（外网默认出口）、WiFi 度量设 60（不抢默认路由）；配置区 `IntranetPrefixes` 的内网网段加静态路由指向 WiFi 网关（ActiveStore，不落盘）
- off：按状态文件精确还原（删自己加的静态路由 + 网卡度量恢复 AutomaticMetric）
- 状态文件：`%LOCALAPPDATA%\net-route-switch\state.json`
- 网卡自动识别：WiFi 按名称/描述匹配 Wi-Fi/WLAN/无线，USB 按 NDIS/RNDIS/USB/Tethering；蓝牙/Sangfor VNIC 排除
- 保险：`$ProtectedPrefixes`（0.0.0.0/0、255.255.255.255/32、224.0.0.0/4）永不删除/不列入静态路由

本机实测（2026-09-11）：
- WiFi `WLAN`（Intel Wi-Fi 6E AX211）= 192.168.1.102/24，网关 192.168.1.1，度量 40
- USB `以太网 2`（Remote NDIS Compatible Device）= 10.247.27.31/24，网关 10.247.27.133，度量 25
- 默认路由已走 USB（25 < 40），内网 192.168.1.0/24 由 WiFi 直连；`status` 实跑正常

踩坑：`write_to_file` 写出的 .ps1 无 BOM，PowerShell 5.1 按 ANSI 解码中文 → 字符串引号被撑破、报一堆假语法错。解决：用
`[IO.File]::WriteAllText($p, [IO.File]::ReadAllText($p,[Text.Encoding]::UTF8), (New-Object Text.UTF8Encoding($true)))` 补 BOM 后再校验（前 3 字节 = 239,187,191）。

待用户确认：内网是否只有 192.168.1.0/24（当前配置区 IntranetPrefixes 为空），若要访问 WiFi 网关后面的其它网段需把网段填进配置或 `-Prefix` 传入。

## 补充：用户确认配置 + 实跑修复（同日 17:00）

用户答复：「内网 172 开头」+ 域名 `https://bar.dayesteel.com.cn/`；「关闭」语义 = 恢复系统默认。

实测到的内网事实：
- `bar.dayesteel.com.cn` → **172.15.115.121**（不在 172.16.0.0/12 里，是 172.15.x）
- WiFi(WLAN) 的 DNS = **172.15.88.1 / 172.15.88.2**（内网 DNS）；USB(以太网 2) 的 DNS = 10.247.27.133
- 修正前故障现象：默认路由走 USB（度量 25 < 40），所以 172.15.x 被送出 USB 网卡 → 内网站点与内网 DNS 全不通
- 配置区已改为 `IntranetPrefixes = @('172.0.0.0/8')`、`IntranetProbes = @('bar.dayesteel.com.cn','172.15.88.1')`

修复的三个 bug：
1. `Resolve-Prefix` 正则 `^(\d{1,3}(\.\d{1,3}){3})/(\d{1,2})$` 里内层 `(...)` 也是捕获组，`$Matches[2]` 取到 `".0"`（`[int]".0"`=0），于是 `172.0.0.0/8` 被解析成 `172.0.0.0/0` → `New-NetRoute` 报「参数错误」。改用命名组 `(?<ip>...)/(?<len>...)`
2. `Set-NetIPInterface -InterfaceMetric` 除改活动存储外，还会把手工度量写进注册表持久存储
   `HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{GUID}\InterfaceMetric`；
   只做 `-AutomaticMetric Enabled`（活动存储）时，USB(NDIS) 网卡一重连就把旧度量又戴上（日志显示恢复后 25，1 分钟后变回 10）。
   → `off` 现在活动存储 + 注册表一起处理：原本是自动的删掉该值，原本是手动的写回原值，并且只删本次写入的值
3. 提权窗口报错看不到 → 运行日志 `%LOCALAPPDATA%\net-route-switch\last-run.log`（含表格）+ 主流程 try/catch

实测验证结论（最终状态）：
- `on`：`172.0.0.0/8 → 192.168.1.1`（RouteMetric 1）；默认路由 以太网 2(10+10=20) 优于 WLAN(60)；`bar.dayesteel.com.cn:443` TCP 可达、内网 DNS 可通、223.5.5.5 与 baidu 走 USB 可通
- `off`：两张网卡度量回到 40/25 且 AutomaticMetric=Enabled，注册表手工度量清空，内网静态路由删除，状态文件清除
- 脚本流程：双击 `tools/net-route-switch.bat` → 1 开 / 2 关 / 3 状态（需点 UAC）
