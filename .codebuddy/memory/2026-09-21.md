- 关键改动（tools/net-route-switch.ps1，已写好，BOM 已保留）：

## 实机应用：插网线后外网立刻断开，原因 + 修复（2026-09-21 同日 16:11）
- 用户接好 Realtek 以太网（IP 172.15.156.180/24、网关 172.15.156.254、DNS 172.15.88.1/.2、主 DNS 后缀 hbxyg.com）后立刻报"自己连不上"（外网断）。
- 根因——**Windows 给以太网 DHCP 自动加了一条默认路由（metric 25），比 WLAN 的 45 低**：status 默认路由表显示 `以太网 172.15.156.254 metric 25` 在 `WLAN 10.68.67.230 metric 45` 之前，所有外网请求都被内网网关接收、不会向外转发。
- 实操：
  1. 改 Config：`IntranetAdapter = @('以太网')`、`InternetAdapter = @('WLAN')`（让自动模式默认走新分工；同时保留旧模式靠 CLI 覆盖）
  2. `Start-Process powershell.exe ... -Verb RunAs` 触发 UAC，用户点「是」→ 管理员 PowerShell 跑 `net-route-switch.ps1 -Action on -IntranetIf 以太网 -InternetIf WLAN -Pause`
  3. 第一次跑时 `Get-NetAdapter` 报以太网 Status=Disconnected（链路其实已 Up 1Gbps，估计 Get-NetAdapter 缓存或瞬时抖动），脚本因此跳过加 172.x 路由；只把 WLAN 度量改成 10，外网恢复
  4. 等几秒再跑一次，Status 这次正常 Up，加上 172.0.0.0/8 → 172.15.156.254（RouteMetric=1）+ 以太网度量改成 60 → 完美分工
- 最终状态：WLAN 度量 10（默认路由胜出）+ 以太网度量 60（不参与默认路由竞争）+ 172.0.0.0/8 静态路由指向以太网网关；测试 5 个目标（bar.dayesteel.com.cn、内网 DNS、内网网关、223.5.5.5、百度）全部可通，分别走对侧网卡
- 经验：**网卡 Status 字段在链路刚 UP 那一刻不可靠**，涉及网卡状态机的脚本应允许重跑或加 retry 等待；本脚本现有"再加一次"的兜底有效

## 傍晚：网线换插到「外网」路由器后连不上网——根因是陈旧 DHCP 租约（同日 ~23:00）
- 用户把网线插到了**烽火(fiberhome)家用路由器**（外网，192.168.124.0/24 段），但 Windows 一直攥着内网的旧租约 172.15.156.180/24 gw 172.15.156.254（租约还剩 7 天），新网络上根本没有这个网关 → ping 172.15.156.254 全超时。
- 之前 off 已还原自动度量：以太网自动 metric 35 < WLAN 45，所以 Windows 优先走这条**死掉的以太网默认路由** → 表现为"网线连着但上不了网"（WLAN 其实能通公网）。
- 链路层线索：以太网 LinkSpeed 从 1Gbps 掉到 100 Mbps（换插路由器百兆口所致）。
- 修复：`ipconfig /release "以太网"` + `ipconfig /renew "以太网"` → 拿到 192.168.124.2 / gw+DNS 192.168.124.1 / DNS 后缀 fiberhome；ping 网关 <1ms、223.5.5.5 25ms、百度域名解析+回包正常。
- 当前格局：**以太网=外网默认出口**（metric 35 胜 WLAN 45）；WLAN 10.68.67.15（gw 10.68.67.230）也能通公网。此刻不在"内网 172.15.x"环境。
- 经验：**换网线插孔/换网络后 Windows 不会主动放弃旧 DHCP 租约**，症状就是"已连接但无 Internet"；一招修复 = release+renew。给同事的版本可考虑在 off/排障提示里写上这句。
