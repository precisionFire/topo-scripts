## net-route-switch v1.3：模式拆分（用户反馈"功能混乱、模式一废了"）
- 背景：v1.2 把 `IntranetAdapter=@('以太网')/InternetAdapter=@('WLAN')` 写成配置默认值后，菜单按 1 / 裸 `on` 的自动识别被模式二劫持。今早 09:45 用户跑了一次 on：插在烽火家用路由器（外网 192.168.124.x）上的以太网被当成内网，还加了错路由 `172.0.0.0/8 → 192.168.124.1`（内网流量往家用路由器塞），state 记录的也是这套错分工。
- v1.3 改动（tools/net-route-switch.ps1，语法 Parser 校验通过）：
  1. 新增 `-Mode 0|1|2`（0=未指定：on 时按 1 处理；status 时按状态文件模式展示）；菜单改为 `1 开模式一 / 2 开模式二 / 3 关闭 / 4 状态 / 0 退出`
  2. 配置区 `IntranetAdapter/InternetAdapter` 取消，改为 `ModeDefs` 按模式定义：模式一留空 = v1.0 自动识别原行为（WiFi=内网、UsbMatch=外网）；模式二 = 以太网类=内网（允许未插线）+ WLAN 类=外网
  3. **修潜伏 bug**：`EthernetMatch` 里的 `'LAN'` 会匹配 `'WLAN'`（"WLAN" 含 "LAN"）→ WiFi 被误判为网线。此 bug v1.0 起就有，之前 USB 在场从未触发到该分支。已从 EthernetMatch 删掉 'LAN'
  4. 内网角色匹配到 Down 网卡时等 2 秒重查一次该 ifIndex，规避链路刚 Up 时 Get-NetAdapter Status 抖动（昨天模式二要跑两次才能成功的根因缓解）
  5. 状态文件记录 `mode`（v1.2 及以前无此字段的迁移为 1）；status 显示优先级：off 后强制模式 > -Mode 显式传入 > 状态文件记录 > 默认 1
- 实测验证（status 无需提权）：`-Mode 1` 内网=WLAN/外网=以太网 ✓；`-Mode 2` 内网=以太网/外网=WLAN + 能看到 172.0.0.0/8 错路由 ✓；不传 Mode 时按 state（09:45 那次）展示 ✓
- **待办（未完成）**：09:45 错跑留下的烂摊子要 off 清理（错路由 + WLAN@10/以太网@60 手工度量）。提权窗口已弹出但用户一直没点 UAC；让用户自己双击 bat 按 3 即可。
- 注意当前物理格局：网线插的是烽火家用路由器（192.168.124.x，外网）；WLAN = 10.68.67.15（也能出公网）。都不在 172.15.x 公司内网环境。
