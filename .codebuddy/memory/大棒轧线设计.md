## 四、架构分层

```
数据源层：dataModel.addDataPropertyChangeListener
  ├─ a:rolltable   → 钢坯热检数据（含速度占位条目）
  ├─ a:coldTable   → 冷床齿槽快照
  └─ a:rolltable1  → 横移台架（平托）钢坯数组
        ↓
事实仓库 SteelFactStore（后端原始数据快照，localStorage）
        ↓ syncFactToState（事件驱动）
状态仓库 SteelStateStore（推演运动状态，localStorage）
   ├─ updateSteelPhase → updateSteelSpeed → applyCollectionPointControl → updateSteelPosition
   ├─ applyPositionCorrection（热检校正，走 forwardSimulatePosition 推算）
   └─ isSteelFinished → cleanupFinishedSteels
        ↓
历史仓库 HmdPassStore（热检经过历史）/ RollY3Store（roll-y3 上下线记录）
        ↓
渲染层：buildRenderData → renderMultipleSteels
   ├─ createSteelLineShapes（每支 2 个 Shape，按段裁剪）
   ├─ updateSteelLines / drawSteel / animateSteelLine（1 秒平滑插值）
   └─ updateSteelStyle（label + border.color）
附加模块：横移台架显示、roll-y3 续显、冷床齿槽显示、DataCollector 曲线、班组班次/最近十卡
```

**运行机制**：`startSteelSimulator()`（2455）定时器每 **100 ms** 执行一次 `updateSteelStates()` → `buildRenderData()` → `renderMultipleSteels()`（`syncFactToState` 已移出定时器，改为数据到达时事件驱动）。

## 五、关键概念

| 名称 | 含义 |
|------|------|
| `inMatNo` | 钢坯唯一标识号（后端 `slabNo` 归一化而来） |
| `headX` / `tailX` | 钢坯头/尾在轧线上的 X 坐标（连续值，逻辑坐标） |
| `state` | 钢坯当前阶段：`ENTRY` / `ROLL1` / `ROUGH` / `ROLL2` / `MIDDLE` / `ROLL3` / `PREFINISH` / `ROLL4` / `FINISH` / `ROLL5` / `UNKNOWN` |
| `headSpeed` / `tailSpeed` | 头/尾当前速度（ENTRY 段 head=5、tail=0；其余查 `SPEED_CONFIG`） |
| `direction` | 往复区内运动方向（+1 正向 / −1 反向），由热检 X 变化推断 |
| `_lastHeadHmdX` | 上次头经过热检的 X（方向推断基准） |
| `_lastHeadHmdTime` / `_lastTailHmdTime` | 已处理的热检时间（防同一 HMD 重复校正） |
| 轨道分段 | 2 条轨道，**长度不等**：roll-y1 = 1800 + roll-y2 = 720，合计 2520 |
| 集合点 | 各辊道/热检节点的"有钢信号"，控制钢坯头尾进退 |

## 六、常量与配置

### 6.1 轨道（两段不等长）

```js
TRACK_LENGTHS     = [1800, 720]   // 99
TRACK_COUNT       = 2             // 100
TRACK_STARTS      = [0, 1800]     // 101-106（累加）
LINE_TOTAL_LENGTH = 2520          // 102
```

- 画布映射统一公式：`canvasX = logicX − TRACK_STARTS[i]`
- 图纸 `track-*` 节点逻辑坐标：`floor(baseX + TRACK_STARTS[trackNum − 1])`（152-173）；`millstate` 节点直接取其 X
- 两条轨道视觉方向一致（钢坯从左→右），跨轨按段裁剪显示

### 6.2 位置映射表

- `PHYSICAL_ORDER`（126-149）：22 个节点 tag 的物理摆放顺序（含 `track-1ShearPre1_5mHotDet` 等 3 处拼写粘连，提防误改）
- `TRACK_POSITION_MAP`（176+）：**仅热检名 → 逻辑 X**，热检校正与离线判定使用
- `All_POSITION_MAP`（178+）：热检 + `millstate` 节点（集合点控制使用）

### 6.3 分区表与速度（⚠️ 中棒残留，见 §十一）

MILL_ZONES = [                                    // 929-939

  ROLL3 1500-1600 / PREFINISH 1600-1800 / ROLL4 1800-3380 /
  FINISH 3380-3550 / ROLL5 3550-5400
];
SPEED_CONFIG = 9 个分区 headSpeed = tailSpeed = 5  // 942-952
ROLLING_ZONE_NAMES = [ROUGH, MIDDLE, PREFINISH, FINISH]  // 1528-1533

### 6.4 往复区（可逆轧机）

## 八、数据源监听与主循环

监听器（2794-2911）用全局 `window.__trackingListenerInstalled` 防重复注册，单监听器内按 `e.property` 分 3 支：

1. **`a:coldTable`**（2800）→ `handleColdTableSnapshot(e.newValue)`（冷床齿槽）
2. **`a:rolltable1`**（2806）→ `showTransverseSteel(e.newValue)`（横移台架钢坯数组，最多 9 支）
3. **`a:rolltable`**（2814+）：钢坯热检数据，流程
   - `msgTime` 校准 `clockOffset`（2819-2824）
   - 首帧 `_startupRebuildDone`：无缓存 → 从 FactStore 全量 `addSteelToState` + `cleanupFinishedSteels`；已从缓存恢复 → 按服务器时间校准 `updateTime`（2827-2845）
   - 末条含 `dischargeSpeed` → 视为速度占位条目并 `Object.assign(SpeedStore, ...)`（2854-2880，`SpeedStore` 为内存对象，2482-2488）
   - 首次 `buildFactBaseline`，之后 `updateFactStore`（2885-2900）
   - `syncFactToState()` + `applyFactCorrections()` + `cleanupFinishedSteels()`（2903-2907）

主循环 `startSteelSimulator()`（2455-2472）：`setInterval(..., 100)`，每帧 `updateSteelStates()` → `buildRenderData()` → `renderMultipleSteels()`。

`updateSteelStates()`（2307-2358，dt 按 `getServerNow()` 差算，非固定 100 ms）：
`updateSteelPhase` → `updateSteelSpeed` → `applyCollectionPointControl` → `updateSteelPosition(dt)` → `isSteelFinished`（收集）→ 批量 `removeSteelFromState` → `RenderCacheStore.snapshot()`。

## 九、业务规则

### 9.1 生命周期与事实仓库

- `addSteelToState`（1179-1270）：唯一性守卫（StateStore 已存在 / 黑名单）→ `forwardSimulatePosition` 推算 + `applyProcessConstraints` 工艺约束 → 建 state（`direction = 1`）
- `normalizeBackendItem`（1339-1344）：`slabNo` → `inMatNo`
- `buildFactBaseline` / `updateFactStore`（1346-1432）：基线 / 增量，离线钢坯移除
- `syncFactToState`（1443-1508）：清无效条目、补新钢坯、批量移除离线

### 9.2 工艺约束 `applyProcessConstraints`（1074-1177，**11 条规则**）

按触发热检名固定钢坯头/尾位置（如 0 / 250 / 778 / 628 / 985 / 835 / 900 / 750 / 903 / 1100 / 2100 等）。
触发热检名：`DescalerBeforeHmd` / `PinchRollBeforeHmd` / `Stand2EntryHmd` / `Stand4EntryHmd` / `Stand6EntryHmd` /
`RollTable6AEntryHmd` / `RollTable6BEntryHmd` / `No1ShearBeforeHmd` / `Stand7/9/12/13/15EntryHmd` /
`No2ShearEntryHmd` / `Stand16ExitHmd` / `No3ShearEntryHmd` / `Stand17EntryHmd` / `No4WaterTankEntryHmd`。
⚠️ 全部沿用中棒工艺，见 §十一。

### 9.3 运动求解（分区变速，**非匀速**）

- `updateSteelPhase`（1595-1627）：按 `headX` 落 `MILL_ZONES` 分区 → state（轧制区取 `ROLLING_ZONE_NAMES` 中的 ROUGH/MIDDLE/PREFINISH/FINISH，其余 ROLL1~ROLL5，未命中 UNKNOWN）
- `updateSteelSpeed`（1637-1669）：ENTRY → head=5 / tail=0；否则查 `SPEED_CONFIG[state]`，无配置 → 0
- `updateSteelPosition`（2068-2105）：`headX/tailX += speed × direction × dt`，tailX 下限 0，含尾部信号安全网
- `forwardSimulatePosition`（2122-2202）：**仍按 `MILL_ZONES` 顺序/逆序消耗剩余时间 × `SPEED_CONFIG` 推算**（末段越界按边界分区速度续算）

### 9.4 集合点信号控制（1671-2063）

`getCollectionNode`(1682) / `getCollectionSignal`(1691，`rolledState` → 有钢信号) / `isActiveCollectionPoint`(1710，millstate 需 `runningState=1`) /
`getNextCollectionPoint`(1729) / `getLastPassedPoint`(1747) / `getTailNextPoint`(1763) /
`canHeadAdvance`(1787，下一集合点信号=1 才可前进) / `getTailReleasePoint`(1844，信号=0 才能离开) /
`applyCollectionPointControl`(1871-1948，**往复区内直接跳过**；4 种情况覆写速度) /
`clipHeadBySignals`(1964) / `clipTailBySignals`(2016，往复区跳过)。
注：集合点长度映射表与 `calculateLengthFromCollectionPoint` 已删除（残留注释 1675 / 1950）。

### 9.5 热检校正 `applyPositionCorrection`（3012-3113）

- 头校正：新 `headPosition + headTime` 且与 `steel._lastHeadHmdTime` 不同才触发 → 记录 `HmdPassStore.recordPass` → `inferDirection(hmdX, _lastHeadHmdX)` 更新方向 → **`forwardSimulatePosition(hmdX, headTime, 'head', direction)` 推算当前位置**（3041）→ `clipHeadBySignals` 约束 → 写回 `headX`（日志 `[钢头校正]`）
- 尾校正：逻辑同上（3076，日志 `[钢尾校正]`）
- 兼容旧格式（只有 `position` 没有 `time`）：直接置位（`[钢头校正(无time)]`，3096-3112）
- 入口 `applyFactCorrections`（2971）由数据监听调用
- **注意**：当前**不是**"直接 `headX = hmdX`"；带 time 的数据一律走分区推算（若推算与现场偏差大，这里就是首要排查点）

### 9.6 下线判定 `isSteelFinished`（2238-2266）

| 条件 | 判据 |
|---|---|
| ① 通用 | `steel.headX >= LINE_TOTAL_LENGTH`（2520，2241） |
| ② 离线热检 | `fact.tailPosition` 命中 `OFFLINE_HMD_LIST`（`No4WaterTankEntryHmd` / `No4ShearBeforeHmd` / `No4ShearExitHmd` / `BslHmd`，268-273） |
| ③ 特殊下线 | `cardNo.indexOf('H8') === 0 && steel.headX >= H8_OFFLINE_HEAD_X`（1800，**大棒一期轧线**） |

命中即写 `finishedInMatNos[inMatNo]` 时间戳（`trimFinishedInMatNos` 2223 只留最近 10 条），由 `cleanupFinishedSteels`（2278-2292）批量移除。

### 9.7 渲染层

- `createSteelLineShapes`（289-328）：每支建 `TRACK_COUNT` = 2 个 `ht.Shape`，tag `steel-{inMatNo}-track-{i}`，挂 `overallBlock`（图纸"整体"块，68-74）
- `updateSteelLines`（343-381）：`[leftX, rightX]` 与各段 `[TRACK_STARTS, +TRACK_LENGTHS]` 求交集 → 相对坐标
- `animateSteelLine`（397-424）：`requestAnimationFrame` 1 秒线性插值（先取消旧动画）
- `drawSteel`（436-534）：新钢坯建 Shape；尾回退且 `direction > 0` → 跳变；否则平滑动画
- `updateSteelStyle`（537-565）：更新 label 与 `border.color`；`buildSteelLabel`（2407）/ `getSteelColor`（2436）
- `renderMultipleSteels`（582-661）：渲染在线钢坯 + 清理离线（取消动画 → `dm.remove` → 清缓存）

### 9.8 横移台架钢坯显示（2502-2634，v1.7 / v1.9）

- 数据：`a:rolltable1` → 钢坯数组（最多 9 支）；`position 0~2` → 固定"动齿"节点（`transverseSteelShapes` 复用，2544 起）；`position 3~8` → `Transverse` 区域纵向排列（3 最下、8 最上），整体上下居中、间距 ≤ 20、上下各留 5px
- 外观：多段线，长度 300、线宽 10，标签「卡号-钢坯号」（`cardNo-slabNo`，`label.position=17`、`setLayer('1')`、16px），Shape 挂 `overallBlock` 随 `fullscreen` 水平缩放同步

### 9.9 roll-y3 离线辊道续显（2636-2789）

- `detectTransverseOffline`（2693）：对比上次平托快照，**本次消失的钢坯** → `addRollY3Steel`（2713）上线到 `roll-y3`
- `tickRollY3Steel`（2760，100 ms）：以 `ROLLY3_SPEED = 10 px/s` 向右匀速前移，头部到达 `ROLLY3_OFF_X = 1800` 下线
- 上下线均记入 `H8_RollY3Store`

### 9.10 冷床齿槽显示（2913-2963）

`a:coldTable` 快照 → 逐齿写图纸节点 `One-{toothNo}`（1~46）：
`displayText` 同时写 `displayText` / `displayContent`（兼容两种绑定），以是否有文字决定 `2d.visible`；`cardNo → CardNumber`、`slabNo → RollPieceID`、`color → Color`（`COLOR_MAP` 未匹配默认 `#ff0000`）。
