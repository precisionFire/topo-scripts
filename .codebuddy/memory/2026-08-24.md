## 弹窗定位改造（DialogCore.js / DialogMain.js）
- 用户反馈 `calcPopupPosition` 的固定禁止区（600~1100 设计坐标）不灵活，改为基于点击节点几何智能定位。
- `DialogMain.js` 新增 `collectNodeGeometry(node)`：用 `graphView.tp()` 将节点逻辑坐标转画布视口坐标，`width/height × zoomFactor()` 换算屏幕尺寸，连同 `getRotation()`（弧度）一并传给 `showSteelPopup`。
- `DialogCore.js` `calcPopupPosition(x, y, rect, nodeGeom)`：
  - 新增 `getRotatedBox()` 计算节点旋转后 AABB 作为空间基准；
  - 新增 `decideDirection(okMap, box, clickX, clickY, longAxisHorizontal)`：**按点击点落在节点哪一侧判定**——点节点左半→弹窗偏右、右半→弹窗偏左、上半→偏下、下半→偏上；节点长轴水平→左右优先，长轴垂直→上下优先；偏好方向空间不足自动换反方向，再降级另一组方向；
  - 不传 nodeGeom 时退回旧行为（居中点击点+边界裁剪），向后兼容。
- 用户偏好：弹窗偏左/偏右、偏上/偏下是看**点击在节点的左/右/上/下部**，不是看节点相对画布的位置。
- **引擎确认**：项目底层是 HT for Web（`graphView`/`dataModel` 全局注入），非 mxGraph。HT 缩放 API 是 `graphView.getZoom()`（无 `zoomFactor()`），坐标转换用 `graphView.tp(x,y)`，节点几何用 `getPosition()/getWidth()/getHeight()/getRotation()`（弧度）。
- **四线弹窗触发链路完全一致**：扁棒/小棒/大棒/中棒加热炉.js 的 onClick 都是 `window.appBridge?.runNodeClickPlugins({node, event, furnaceKey, selectedNodes})` → Dispatcher.js → DialogMain.js 插件 → showSteelPopup。所以弹窗定位改造**不需要改任何产线界面脚本**，只改了弹窗组件。
- **弹窗不遮节点（重要用户诉求）**：showSteelPopup 先 append（visibility:hidden）测量 offsetWidth/offsetHeight 真实尺寸，再传给 calcPopupPosition；calcPopupPosition(x,y,rect,nodeGeom,popupW,popupH) 用真实尺寸判定。弹窗永远贴节点包围盒外侧放（左/右/上/下），避让轴**不做**会压回节点的裁剪（宁可轻微出界）；四周都放不下时选剩余空间最大的方向，移除原"点击点居中"的 center 分支。
- **v3 算法核心**：判定"方向可放"必须**弹窗矩形与节点 AABB 完全不相交 + 弹窗在画布内**——左右方向要求弹窗垂直跨度与节点无交集，上下方向要求弹窗水平跨度与节点无交集（光看画布空间会误判，因为弹窗垂直居中跨过节点会盖节点）。全部放不下时用 `intersectAreaInDirection` 选相交面积最小的方向。`canPlaceInDirection` 在 `DialogCore.js`。
- **关键坑（v4 修复）**：该环境 HT 引擎（ht-vector.js）**没有 `graphView.tp()`**，导致 collectNodeGeometry 抛 TypeError、nodeGeom 恒为 null、永远退回旧逻辑（弹窗盖节点）。修复：改用**点击点标定法**——点击点视口坐标 `(clientX-rect.left)` 已知，点击点逻辑坐标用 `graphView.getLogicalPoint(event)`（HT 标准 API，扁棒/中棒轧机在用），由 `vp = zoom*lp + offset` 反推 offset，再换算节点中心视口坐标；缩放用 `graphView.getZoom()`（typeof 兜底 zoomFactor/1）；节点坐标优先 `getAbsolutePosition()`（父节点挂载）。
- 调用链：中棒线加热炉.js 炉内节点 onClick → runNodeClickPlugins → DialogMain.js → showSteelPopup。
