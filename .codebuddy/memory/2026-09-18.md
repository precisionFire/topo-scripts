## 小棒线二号加热炉：部分前移/后移接口“时发时不发”修复
- 根因：10.4 的 `view.addEventListener('click', ..., true)`（capture）里，用来“忽略右键菜单项点击”的 class 选择器 `.ht_contextmenu, .ht-widget-contextmenu, [class*="contextmenu"]` 在 HT 库中并不存在（ht.js 中 “contextmenu” 只作为事件名出现，无对应 CSS class），因此保护失效。
- 后果：菜单通过 `contextmenu.addTo(view)` 挂在 view 内，点菜单项会冒泡到 view；capture 监听先于 HT 的 action 触发，往下执行 `graphView.getDataAt(e)` 命中的是菜单覆盖区域下的画布内容（空白/轨道 Shape），非炉内节点时执行 `sm().ss(null)` + `_ctx=null`，随后 action 触发 `handleMenuClick` 因 `if (!ctx) return` 直接返回，接口不发请求。
- “时好时坏”原因：取决于菜单弹出位置下覆盖的坐标是否恰好在炉内节点(One-xx)上 —— 覆盖到炉内节点则不清空、能发；覆盖到空白/轨道则清空、不发。
- 修复：把判断改为用 `contextmenu.getView().contains(e.target)`（实例 DOM 判断），不再依赖 HT 内部 class 名。
- 注意：同类文件（小棒线一号、大棒一号、大棒二号、中棒线加热炉）均有相同 10.4 写法，存在同样隐患，待确认是否一并修复。

## 小棒线二号加热炉：部分移动“时发时不发”真正根因（选择集混入非炉内图元）
- 通过调试打印确认：点“部分前移”时 `sm().toSelection()` 里有 30 个节点，但只有 5 个是真正炉内钢坯（tag=One-60~64，有 pos/inMatNo/furnace），其余 25 个是 tag/pos/inMatNo 全为 undefined 的非炉内图元（轨道 Shape/标记节点等）。
- 根因：`extractSelectedRange()` 对选择集按 `pos` 排序，undefined pos 会按 0 参与排序排在最前，导致 `firstNode/lastNode` 取到杂项，`firstPos/firstMatNo` 为 undefined，`range.firstPos !== undefined` 判断不通过 → 不发请求。框选时杂项是否混入不确定，故表现“时发时不发”。
- 修复：新增 `isFurnaceSteelNode(node)`（tag 匹配 `/^(One|Two)-\d+$/`），在 `setVisibleFunc`（count 统计）、`confirmMultiSelect`、`extractSelectedRange` 三处都用它过滤，只保留炉内钢坯节点。
- 另发现：日志中 One-64~One-60 各出现两次（[2]~[6] 与 [17]~[21]），疑似 positionMap/渲染存在重复节点，但不影响部分移动接口（只取首尾 pos）。待确认是否需排查重复节点来源。

## 小棒线二号加热炉：One 节点重复出现（64~68 等）根因确认
- 通过增强打印（id/class/parentId）确认：运行时 dm 里存在**两套完全对称的"炉内坯信息"区块**，每套都含 "加热一段" + One-69~73 + 一批 ht.Text 节点。两套 One-73 的 id 分别是 869（parentId=644）和 400（parentId=175），inMatNo 完全相同。
- 图纸 JSON `小棒线二号加热炉.json` 里 `"tag":"One-73"` 只有一处（i=12581，parent=__i:12356"炉内坯信息"），One-7~119 每个 tag 均唯一 → 图纸里只有一套，重复是**运行时**产生的。
- 根因在入口 HTML `AriView/storage/导入后出现的html文件/小棒线二号加热炉.html`：图纸被 `graphView.deserialize` 了**两次**：
  1. `$(function(){...})` 里 `graphView.deserialize(getParam('tag'), ...)`（URL 的 tag 参数指向该图纸）；
  2. `<body onload='setTimeout(init,300)'>` → `init()` 里 `graphView.deserialize('displays/DaYeTeGang/小棒线二号加热炉.json', ...)`（固定路径，同一图纸）。
  - 两处 deserialize 都向同一个 `graphView.dm()` 追加节点（`changPage` 里要先 `dm().clear()` 再 deserialize，说明 deserialize 不自动清空），导致两套节点、id 被 HT 重新分配成两段（226~419 与 695~888）。
- 两套 inMatNo 都相同的解释：数据源 `a:A2-inside` 在两次 deserialize 前后都有推送，renderFurnaceInsideLayer 每次按当时的 positionMap（`dm.getDataByTag` 只取后注册的那套）渲染，两次各写了一套。
- 当前功能已被 `isFurnaceSteelNode` 过滤兜住（只取首尾 pos，重复不影响接口参数）；根治需修 HTML 去掉重复 deserialize（涉及 AriView 只读部署包，待用户确认）。
- 教训：AriView 场景 HTML 的 `<body onload='setTimeout(init,300)'>` 与 `$(function)` 里各有一处 deserialize，属复制粘贴残留，同类 25 个场景 HTML 可能都存在，改前先确认。
