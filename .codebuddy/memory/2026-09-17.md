## 大棒线轧机.js 逻辑层梳理（只读，未改代码）
- 架构：事件驱动喂事实（a:rolltable → 校时 clockOffset → buildFactBaseline/updateFactStore → syncFactToState → applyFactCorrections → cleanupFinishedSteels）+ 100ms 裸 setInterval 前端自主推演（updateSteelStates → buildRenderData → renderMultipleSteels）。
- 4 个 localStorage 仓库（key 前缀 H8_）：SteelFactStore（后端原始快照，唯一可信源）/ SteelStateStore（推演后运动状态，渲染数据源）/ RenderCacheStore（每帧最终渲染位置，<5s 新鲜则启动复原，否则清空全量重建）/ HmdPassStore（热检经过历史，去重+位置回退告警，上限 50 条）。启动后首次收到 rolltable 时做一次全量重建（_startupRebuildDone）。
- 推演 5 步流水线（文件头 ~1492 行有说明）：updateSteelPhase（length<150→ENTRY；覆盖轧制区用区名；否则按 headX 定位）→ updateSteelSpeed（ENTRY 头 5 尾 0；查 SPEED_CONFIG，现全为 5/5）→ applyCollectionPointControl（头/尾布尔组合 4 种情况覆写速度；尾释放速度 = min(距离×10, 50)）→ updateSteelPosition（speed×dt，dt 用 updateTime 真实差值不是固定 0.1s，含尾部信号安全网）→ isSteelFinished（headX ≥ LINE_TOTAL_LENGTH 2520，或尾经过 OFFLINE_HMD_LIST）。
- 集合点控制语义（关键）：头要「下一个集合点信号=1」才放行，尾要「信号=0 且头已过该点」才释放；信号读取顺序 rolledState → 有钢信号；millstate* 还需 runningState===1 才活跃；顺序依赖 All_POSITION_MAP（按 PHYSICAL_ORDER 插入的 Map）。两道闸门同语义：推演期 applyCollectionPointControl + updateSteelPosition 安全网，校正期 clipHeadBySignals / clipTailBySignals 硬裁切。
- 校正优先级：addSteelToState 时工艺约束（applyProcessConstraints 11 条规则）覆盖纯推算；运行中前端推演为底，后端 headTime/tailTime 变化时用 forwardSimulatePosition 重算再裁切，靠 _lastHeadHmdTime/_lastTailHmdTime 去重。
- 新发现问题：`SpeedStore`（约 2403 行）只被 Object.assign 写入、**全文件无任何读取处** → 后端速度参数（dischargeSpeed/rgExitSpeed/...）实际不参与推演，SPEED_CONFIG 注释说"运行时会被后端推送覆盖"但那段代码不存在。**需要补一根线把 SpeedStore 映射到 SPEED_CONFIG**（待确认现场速度是否真的有数据）。
- 其他风险：finishedInMatNos 黑名单 LRU 仅 10 条，同一时刻下线钢坯超过 10 根时可能淘汰最早者 → 若后端仍在推送该钢坯存在复活可能。

## 结论：当前不支持钢坯"局部往复/后退"运动（只读分析，未改代码）
- 求解器是严格单向模型，证据（均在 大棒线轧机.js）：`updateSteelPosition`(2056) 只有 `+= speed*dt`；而所有速度来源都 ≥0 —— `updateSteelSpeed`(1639) 查 SPEED_CONFIG（全 5/5，ENTRY 头5尾0，查不到→0）、`applyCollectionPointControl`(1873) 4 种情况只把速度设为 0 或正的释放速度 `min(距离×10,50)`(1901)；`clipHeadBySignals`(1961)/`clipTailBySignals`(2009) 开头 `proposedX <= 当前X → return`，只拦前进不会回拉；`forwardSimulatePosition`(2108) 单调向前；`getTailReleasePoint`(1853) 尾被头卡住；`tailX < 0 → 0`(2068)。
- 历史上"非连续前进"的实现全是向前跳变/停顿（中棒线仍保留：applyTailJumpAt1750/3100/3350 尾向前跳 50、applyLengthLockAt620、applyHeadBlockAt1000、applySteelPauseAt1100），大棒线 v1.1 已全部删除，没有任何后退实现。
- 渲染层本身能画后退：`updateSteelLines`(354) 用 min/max 取交集与 head/tail 大小无关；`animateSteelLine`(408) 是 from→to 线性插值，to<from 即倒着走。**唯一阻碍**：`drawSteel`(447) 分支 2 `if (steel.tailX < last.tailX)` 把"尾部回退"当作被裁切处理 → **直接跳变不播动画**(501-511)，往复（头尾同退）必然命中该分支，视觉上会瞬间跳回去。
- 要支持往复需改两处：①逻辑层新增往复插件（tracker 记录 phase/折返点/回程点，把 head/tailSpeed 设成**负值**，`updateSteelPosition` 无需改）；注意 `applyPositionCorrection`(2637) 会用 forwardSimulatePosition 把后退中的钢坯拉回前进方向 → 需给 steel 加往复标记让其跳过校正，边界还要限制在第一段 0~1800 内。②渲染层分支 2 判据要放宽（改为按位移阈值判跳变，或识别往复标记后走 animateSteelLine）。
- 待用户确认的现场参数：往复触发信号源、行程（折返点/回程点）、后退速度与节奏、终止条件（固定次数 or 信号驱动）、头尾是整体平移还是仅头动。
