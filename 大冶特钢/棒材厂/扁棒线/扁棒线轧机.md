# 扁棒线轧机.js 设计文档

> **文件路径**: `扁棒跟踪/扁棒线轧机.js`
> **总行数**: ~3734 行
> **功能**: 扁棒线钢坯运动模拟与可视化

---

## 1. 功能概述

1. 接收后端推送的钢坯热检（HMD）经过数据，推算钢坯头/尾位置
2. 通过分区分速模型模拟钢坯在轧线上的连续运动
3. 将运动状态渲染为双轨道钢坯多段线（polyline）图形
4. 管理钢坯生命周期：进入 → 运动 → 下线

---

## 2. 架构分层

```
┌─────────────────────────────────────────────┐
│  数据源层：dataModel 属性监听 (a:rolltable)    │  ← MQTT推送
├─────────────────────────────────────────────┤
│  事实仓库：SteelFactStore (后端原始数据快照)     │
├─────────────────────────────────────────────┤
│  状态仓库：SteelStateStore (前端推演运动状态)    │
│     ├── 状态判定 → 速度求解 → 位置求解          │
│     └── 热检位置校正 (applyPositionCorrection)  │
├─────────────────────────────────────────────┤
│  历史仓库：HmdPassStore (热检经过历史记录)       │
├─────────────────────────────────────────────┤
│  渲染层：buildRenderData → renderMultipleSteels │
│     ├── createSteelLineShapes (创建图形)       │
│     ├── updateSteelLines     (更新显示)       │
│     └── animateSteelLine     (平滑动画)       │
└─────────────────────────────────────────────┘
```

### 关键概念

| 字段 | 含义 |
|------|------|
| `inMatNo` | 钢坯唯一标识号 |
| `headX` / `tailX` | 钢坯头/尾在轧线上的X坐标（连续值，右→左递减） |
| `state` | 钢坯当前阶段：ENTRY / ROUGH / MIDDLE / PREFINISH / FINISH / ROLL1~5 |
| `headSpeed` / `tailSpeed` | 头/尾当前移动速度 |
| `segmentLength` | 单轨长度 1800 |

### 运行机制

- **定时器** 每 100ms 执行一次主循环 `startSteelSimulator`
- 每次循环：运动推演 → 数据同步 → 渲染更新
- 后端数据到达时事件驱动触发校正，修正前端推演累积误差

## 3. 坐标系统

### 3.1 逻辑坐标（全局）

钢坯在全局坐标系中从右至左运动，`headX` / `tailX` 递减：

```
逻辑X:  3600 ◄────────── 1800 ◄────────── 0
         ├─── track 2 ────┤─── track 1 ────┤
```

### 3.2 画布坐标映射

统一公式 `canvasX = logicX - trackStart`，两条轨道视觉方向一致（右→左）：

| 轨道 | trackIndex | 画布X范围 | 对应逻辑X | 映射公式 |
|------|-----------|----------|----------|----------|
| track 1 (roll-y1) | 0 | 0 → 1800 | 0 → 1800 | `canvasX = logicX` |
| track 2 (roll-y2) | 1 | 0 → 1800 | 1800 → 3600 | `canvasX = logicX - 1800` |

```
  逻辑X:  3600 ◄──────────── 1800 ◄──────────── 0
           ◄── 钢坯运动方向 ── ◄── 钢坯运动方向 ──
  
  画布:
  track 2: 0 ◄───────── 1800    (logicX - 1800)
  track 1: 0 ◄───────── 1800    (logicX - 0)
           ◄── 视觉方向一致 ── ◄── 视觉方向一致 ──
```

### 3.3 热检节点坐标（按物理顺序）

```
轨道1 (track-1)：逻辑X 1797 → 74
  ┌────────────────────────────────────────────────────┐
  │ DescalerBeforeHmd (1797)                           │
  │ Stand1EntryHmd → millstate1~8 → Stand8ExitHmd     │
  │ RollTable1EntryHmd → RollTable2EntryHmd             │
  │ No1ShearBeforeHmd                                   │
  │ millstate9~16 → Stand16ExitHmd                     │
  │ No2ShearBeforeHmd (74)                              │
  └────────────────────────────────────────────────────┘

轨道2 (track-2)：逻辑X 3580 → 2249
  ┌────────────────────────────────────────────────────┐
  │ millstate17~23                                      │
  │ Mill3CutHotHmd → No3ShearBeforeHmd                 │
  │ BslHmd (2249)  ← 下线检查点                       │
  └────────────────────────────────────────────────────┘
```

### 3.4 Y 坐标

| 轨道 | 节点 tag | Y 坐标来源 |
|------|---------|-----------|
| track 1 | `roll-y1` | 图纸节点 y 坐标（约 250） |
| track 2 | `roll-y2` | 图纸节点 y 坐标（约 606） |

## 4. 数据仓库

### 4.1 SteelFactStore — 事实仓库

存储后端推送的原始数据快照。

- **字段**: `initialized`, `data: {inMatNo → 后端原始数据}`
- **LocalStorage Key**: `H9_SteelFactStore`
- **方法**: `load()`, `save()`

### 4.2 SteelStateStore — 运动状态仓库

存储前端推演的钢坯运动状态，是渲染层的数据源。

- **字段**: `data: {inMatNo → 钢坯状态对象}`
- **钢坯对象字段**:
  - `inMatNo`, `cardNo`, `furnaceCode`, `color`
  - `headX`, `tailX`, `headSpeed`, `tailSpeed`
  - `state`, `updateTime`
  - `_lastHeadHmdTime`, `_lastTailHmdTime`（防重复校正）
- **LocalStorage Key**: `H9_SteelStateStore`
- **方法**: `load()`, `save()`

### 4.3 HmdPassStore — 热检经过历史

记录每根钢坯头/尾经过各热检的时间点，用于位置回退检测。

- **字段**: `data: {inMatNo → {passes: [{type, position, time, x}]}}`
- **LocalStorage Key**: `H9_HmdPassStore`
- **方法**: `recordPass()`, `hasTailPassed()`

### 4.4 RenderCacheStore — 渲染缓存

用于页面刷新时恢复画面状态。

- **方法**: `save()`, `load()`

## 5. 数据流

```
MQTT 推送
    │
    ▼
sbind.js → dataModel.a('rolltable') = data
    │
    ▼
dataModel.addDataPropertyChangeListener  ← 事件入口
    │
    ├─► 时钟校准 (clockOffset)
    ├─► 分离速度数据 → SpeedStore
    ├─► 分离钢坯数据 → buildFactBaseline / updateFactStore
    │       │
    │       ├─► SteelFactStore (存储后端原始数据)
    │       ├─► addSteelToState (新钢坯进入 StateStore)
    │       └─► removeSteelFromState (离线钢坯移除)
    │
    ├─► syncFactToState (FactStore ↔ StateStore 同步)
    ├─► applyFactCorrections → applyPositionCorrection (位置校正)
    └─► cleanupFinishedSteels (清理已下线钢坯)
    
定时器 (100ms)
    │
    ▼
startSteelSimulator
    │
    ├─► updateSteelStates      ← 运动推演
    │     ├─ updateSteelPhase       (状态判定)
    │     ├─ updateSteelSpeed       (速度求解)
    │     ├─ applyCollectionPointControl (集合点控制)
    │     ├─ applyTailJumpAt1750    (尾跳1750)
    │     ├─ applyTailJumpAt3100    (尾跳3100)
    │     ├─ applyTailJumpAt3350    (尾跳3350)
    │     ├─ applySteelPauseAt1100  (修磨停顿)
    │     ├─ updateSteelPosition    (位置求解)
    │     └─ isSteelFinished        (下线判定)
    │
    ├─► buildRenderData        ← 构建渲染模型
    └─► renderMultipleSteels   ← 渲染到画面
```

## 6. 核心函数

### 6.1 坐标解析

| 函数 | 功能 |
|------|------|
| `resolvePositionX(positionName)` | 解析后端位置名→X坐标，先查 TRACK_POSITION_MAP，再查 BACKEND_POSITION_ALIASES |
| `logicToCanvasX(visibleStart, visibleEnd, trackIndex)` | 逻辑坐标→画布坐标映射 |
| `processRenderCoords(headX, tailX)` | 计算层坐标→渲染层归一化 `{leftX, rightX}` |
| `getYTrack(index)` | 获取轨道的 Y 坐标 |

### 6.2 生命周期管理

| 函数 | 功能 |
|------|------|
| `addSteelToState(item)` | 新钢坯进入轧线，初始化状态并加入 StateStore |
| `removeSteelFromState(inMatNo)` | 钢坯下线，从 StateStore 移除，清理所有 tracker 和 Shape |
| `isSteelFinished(steel)` | 判定钢坯是否已下线：`headX <= 0` 或 tailPosition 为 BslHmd |
| `cleanupFinishedSteels()` | 批量清理 StateStore 中已下线钢坯 |
| `cleanupSteelTrackers(inMatNo)` | 统一清理钢坯所有 tracker 数据 |

### 6.3 数据同步

| 函数 | 功能 |
|------|------|
| `buildFactBaseline(rawData)` | 首次接收数据，建立 FactStore 基线 |
| `updateFactStore(rawData)` | 增量更新 FactStore，处理新增/离线钢坯 |
| `syncFactToState()` | FactStore 与 StateStore 双向同步 |
| `applyFactCorrections()` | 遍历 FactStore，对 StateStore 中钢坯执行位置校正 |
| `applyPositionCorrection(fact, steel)` | 头/尾位置校正：从 HMD 时间正向推算新位置并覆盖 |
| `normalizeBackendItem(item)` | 后端数据归一化：`slabNo` → `inMatNo` |

### 6.4 运动推演

| 函数 | 功能 |
|------|------|
| `updateSteelStates()` | 主推演循环：状态判定→速度求解→位置求解→离线判断 |
| `updateSteelPhase(steel)` | 根据位置判定钢坯当前阶段 |
| `updateSteelSpeed(steel)` | 根据阶段查表获取头/尾速度 |
| `updateSteelPosition(steel, dt)` | `headX -= headSpeed × dt`，边界约束 |
| `forwardSimulatePosition(startX, startTimeStr, speedType)` | 从 HMD 经过位置+时间正向推算当前实际位置 |

### 6.5 集合点控制

| 函数 | 功能 |
|------|------|
| `getCollectionNode(tag)` | 获取集合点对应的图纸节点 |
| `getCollectionSignal(tag)` | 读取集合点有钢信号（1=有钢, 0=无钢） |
| `isActiveCollectionPoint(tag)` | 判定集合点是否活跃（track-*始终活跃，millstate需运行中） |
| `getNextCollectionPoint(headX)` | 获取头下一个即将经过的集合点 |
| `getLastPassedPoint(headX)` | 获取头上一次经过的最后一个集合点 |
| `getTailNextPoint(tailX)` | 获取尾下一个需要经过的集合点 |
| `canHeadAdvance(steel)` | 判定头能否前进（下一集合点信号=1） |
| `getTailReleasePoint(steel)` | 判定尾能否释放（下一集合点信号=0且头已过） |
| `applyCollectionPointControl(steel)` | 根据集合点信号覆写头尾速度（4种情况） |
| `clipHeadBySignals(steel, proposedHeadX)` | 头位置裁切：不越过信号≠1的集合点 |
| `clipTailBySignals(steel, proposedTailX)` | 尾位置裁切：不越过信号≠0或头未过的集合点 |

### 6.6 工艺约束插件

| 函数 | 功能 |
|------|------|
| `applyTailJumpAt1750(headX)` | 头越过1750时，尾跳至下一集合点前50 |
| `applyTailJumpAt3100(headX)` | 头越过3100时，尾跳至下一集合点前50 |
| `applyTailJumpAt3350(headX)` | 头越过3350时，尾跳至2100 |
| `applySteelPauseAt1100(headX)` | 头到1100时停顿10秒（1#剪修磨工艺） |
| `applyProcessConstraints(steel)` | 工艺约束入口（集合点长度控制等） |

### 6.7 渲染层

| 函数 | 功能 |
|------|------|
| `createSteelLineShapes(steel)` | 为钢坯创建2个轨道 Shape |
| `updateSteelLines(rollnum, leftX, rightX)` | 更新钢坯在2条轨道上的显示（跨轨裁剪） |
| `animateSteelLine(rollnum, ...)` | 1秒平滑过渡动画 |
| `buildRenderData()` | 从 StateStore 构建渲染模型数组 |
| `buildRenderModel(steel)` | 单条钢坯渲染模型（追加 label, color 等） |
| `renderMultipleSteels(renderData)` | 批量渲染所有钢坯到画面 |
| `buildSteelLabel(steel)` | 生成钢坯标签 "卡号-炉号-支数" |
| `getSteelColor(steel)` | 钢坯颜色映射 |
| `getSteelLength(steel)` | 钢坯长度计算 |
| `startSteelSimulator()` | 启动主循环定时器（100ms） |

### 6.8 工具函数

| 函数 | 功能 |
|------|------|
| `getServerNow()` | 返回校准后的服务器时间 |
| `trimFinishedInMatNos()` | finishedInMatNos LRU 控制（最多10条） |
| `trimCollectionTracker()` | steelCollectionTracker LRU 控制（最多10条） |

## 9. 数据源监听

监听 `dataModel` 的 `a:rolltable` 属性变化，后端通过 MQTT 推送数据。

**数据格式**:
```
{
  msgTime: "2026-08-10 17:53:46.707",   // 服务器时间
  data: [
    { inMatNo, cardNo, furnaceCode, headPosition, headTime, tailPosition, tailTime, color },
    ...,
    { dischargeSpeed, rgExitSpeed, ... }  // 最后一项可能是速度参数
  ]
}
```

**处理流程**:
1. 用 msgTime 校准 clockOffset
2. 启动重建（如果首次且无缓存）
3. 分离速度数据 → SpeedStore
4. 分离钢坯数据 → buildFactBaseline / updateFactStore
5. syncFactToState → applyFactCorrections → cleanupFinishedSteels
